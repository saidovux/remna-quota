# Безопасность API

- `BACKEND_API_KEY` доступен только доверенному серверному приложению — сайту, боту или другому клиенту. Он административный: приложение проверяет владельца набора и права на исходные подписки. `external_ref` и `metadata` не создают границ доступа. Общий ключ нельзя передавать конечным пользователям.
- Генерируйте отдельные случайные ключи для API и PostgreSQL. `.env` не отслеживается; в Linux задайте ему права `0600`.
- Общий URL `/sub/{token}` — секрет. Токен содержит 32 случайных байта, поиск выполняется по SHA-256; исходный токен хранится в закрытой базе для повторного получения ссылки. Резервные копии базы тоже секретны.
- Замена токена меняет общую ссылку, сохраняя VPN-ключи. В основном API accounts отключение аккаунта/части синхронизируется с пользователями панели. В дополнительном API bundles исключение источника или удаление набора меняет только общую выдачу, не исходный VPN-доступ.
- Resolver доступен только с серверным API-ключом и не создаёт сессию пользователя. Если интегратор использует владение ссылкой для авторизации, он сам ограничивает права такой сессии и сверяет отпечаток с текущей ссылкой для отзыва после ротации. Владение VPN-ссылкой не должно автоматически давать доступ к платежам и настройкам владельца.
- Ответы имеют `Cache-Control: no-store` и `Referrer-Policy: no-referrer`. Прокси и аналитика не должны сохранять секретные URL или заголовки авторизации.
- Приложение не журналирует тела запросов, общие ссылки и сырые ответы панели. Внешние ошибки преобразуются в машинные коды. API не раскрывает переменные окружения и конфигурацию.
- Адаптер Remnawave не переходит по редиректам, использует фиксированный адрес панели, ограничивает размер ответа и тайм-аут. Произвольные URL для получения подписок не принимаются.
- Управление пользователями включено по умолчанию. Адаптер изменяет только пользователей с точным маркером принадлежности и восстанавливает сохранённые настройки. Токену нужны права создания, чтения, изменения, включения/отключения и выдачи connection keys; права удаления и сброса не требуются.
- Дополнительный API bundles читает явно указанные ID существующих подписок без их изменения. Для установки только с этим сценарием явно задайте `BACKEND_ENABLE_MANAGED_ACCOUNTS=false` и используйте токен только для чтения.
- Измерения и фактическую блокировку обеспечивает провайдер; remna-quota хранит расход и синхронизирует независимые ограничения. При ошибке панели общая ссылка возвращает ошибку, чтобы клиент не принимал случайный неполный список за обновлённую подписку; заведомо исчерпанные/отключённые части исключаются независимо.
- Сервис не реализует управление ролями операторов и распределённое ограничение частоты запросов. Размещайте административные маршруты в доверенной сети; для публичного маршрута задайте ограничения на прокси.

Для старого контроллера сохраняются его настройки из `.env.legacy.example`; новый сервис не использует `WRITE_MODE` или `LIVE_TEST_CONFIRM`.
