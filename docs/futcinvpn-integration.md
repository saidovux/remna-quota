# Подключение FutcinVPN

Сайт `https://futcinvpn.pxoxq.xyz` подключён к remna-quota 25 сентября 2026 года (МСК). Он использует обычные REST API и Go SDK, доступные другим сайтам и ботам. Специальные платёжные методы в quota не добавлялись; Xray и Remnawave не изменялись.

## Настройки

В окружении **бэкенда сайта**, общем для API и воркера:

```dotenv
QUOTA_BASE_URL=https://accountrd.pxoxq.xyz
QUOTA_API_KEY=<серверный BACKEND_API_KEY remna-quota>
```

Caddy направляет `/api/v1/*` домена подписок в quota. Эти маршруты требуют Bearer-ключ; публичные `/sub/{token}` сохраняют прежний адрес. Порт quota остаётся привязан к loopback. Ключ не передаётся браузеру и не используется в `VITE_*`.

## Модель интеграции

- UUID каждой независимой подписки сайта соответствует `account.id` quota. UUID покупателя записывается в `external_ref`. Две покупки одного человека создают разные аккаунты quota.
- Сайт хранит покупателей, заказы и снимок приобретённого доступа. Коммерческие правила остаются в его бэкенде. В quota передаются только технические параметры частей MAIN/CDN.
- remna-quota создаёт пользователей панели с суффиксами `_main`/`_cdn`, управляет их настройками и возвращает общую ссылку и раздельные показатели.
- Remnawave и штатные ноды измеряют трафик и применяют ограничения. Подключение сайта не меняет ограничений штатной Xray на уже открытые соединения.

Миграция сайта `00003_quota_integration.sql` добавляет `subscriptions.quota_account_id` и таблицу `quota_provisions`. Последняя хранит неизменяемый запрос выдачи для каждого оплаченного заказа: абсолютные квоты, сроки, идентификатор и ожидаемую revision.

Конструктор и готовые предложения разбирает Go-бэкенд сайта. Воркер использует сохранённый снимок покупки. Перед первым изменением quota он сохраняет рассчитанный запрос в PostgreSQL сайта. Повторный webhook, перезапуск или потеря ответа используют тот же UUID и запрос; `expected_revision` защищает от перезаписи чужих изменений.

`202` означает ожидание синхронизации. Подписка становится активной только после `sync_status=ready` и `stale=false`. Ожидание повторяется через десять секунд, не исчерпывая счётчик ошибок активации.

Выбранное правило сайта для конечного пакета: приобретённые байты добавляются к большему из прежнего абсолютного лимита и наблюдаемого расхода. Это сохраняет остаток и даёт весь новый пакет, в том числе при переходе с безлимита. Расчёт фиксируется один раз на заказ; счётчики не сбрасываются. Для выбранной части срок увеличивается от более позднего значения — текущего времени или прежнего окончания. Не выбранная часть сохраняет квоту и срок. Другой интегратор может задавать другую политику, используя те же абсолютные параметры API.

Старые записи с `remnawave_user_id` сохраняют прежний обработчик. При подключении в production-БД сайта было ноль подписок, поэтому перенос действующих покупок не требовался. Существующих пользователей панели нельзя присваивать по совпадению username.

## Кабинет и вход по ссылке

В каждой подписке кабинета — одна общая ссылка/QR и отдельные MAIN/CDN: расход, остаток, срок и состояние. Неизвестный расход не подменяется нулём; устаревшие снимки отмечаются. Общий остаток разных квот не вычисляется.

Вход по объединённой ссылке использует защищённый `POST /api/v1/subscriptions/resolve`. HttpOnly-сессия сайта содержит ID аккаунта и отпечаток ссылки. Она открывает только эту подписку, без email и платежей. Смена токена quota отзывает такой доступ. Прежний вход по нативным ссылкам сохранён.

Для управляемых подписок показываются текущие показатели quota. График за семь дней скрыт: API текущих снимков не предоставляет исторический ряд. Для прежних нативных подписок график сохранён.

Число устройств из сохранённого снимка покупки передаётся как `device_limit` общего аккаунта quota. MAIN и CDN используют один список HWID. Кабинет показывает число зарегистрированных устройств и общий лимит. Повторный webhook и продление не обнуляют список. Старые предложения без числа устройств сохраняют прежнюю настройку. Подробнее: [HWID и управление устройствами](hwid.md).

## Проверки выпуска

- Go-тесты, PostgreSQL-интеграция, race detector и `go vet` прошли. Обновление тестовой БД с версии 2 до 3 сохранило старую нативную подписку.
- Проверены потеря ответа, повтор после перезапуска, `202`, конфликт revision, независимость частей и изменение конечной квоты.
- Изолированный сайт с двумя воркерами проверен с реальным quota: две покупки, повторные webhook, отдельное продление CDN, общая ссылка, кабинет и отзыв сессии при смене ссылки. Два временных аккаунта отключены; их синхронизация после отключения — `ready`.
- Frontend: lint, typecheck, 10 тестов; браузерные проверки desktop/mobile — 16/16 на отдельном сайте и 16/16 после обновления production.
- В production проверены вход по прежней общей ссылке Oleg, две части в кабинете, `401` для API quota без ключа и кабинета без авторизации.
- `/api/health` проверяет базу, авторизацию, Remnawave и quota; все проверки успешны.

Production-платежи остаются выключенными (`PAYMENT_PROVIDER=disabled`). Покупки проверялись с mock-провайдером только в отдельной БД. Подключение реального платёжного провайдера не входило в выпуск.

## Развёртывание и восстановление

Исходники сайта: `/opt/futcinvpn` на его сервере. Версия миграций business-БД: **3**. Образы API/worker и Caddy: тег `20260924-quota`.

Резервная копия сайта: `/opt/futcinvpn-backups/quota-integration-20260924T213627Z`. Содержит исходники, окружение, дамп БД, прежние образы и `rollback-images.yml`. Старый воркер остановлен до миграции и запуска нового.

Резервная копия quota перед изменением прокси: `/opt/remna-quota-test/website-integration-backup-20260924T184513Z`. Бинарный файл и схема quota этим подключением не менялись.

Перед откатом образов учитывайте новые записи `quota_account_id`: старый сайт их не показывает. Восстанавливать прежнюю БД поверх новых заказов автоматически нельзя. Сами VPN-ссылки обслуживаются отдельным quota и не зависят от версии фронтенда сайта.

Локальная копия исходников сайта: `tmp/futcinvpn-integration`, исключена из git репозитория quota. В `backend/third_party/remna-quota` находится закреплённая копия публичного Go SDK с лицензией. Рабочий код сайта не включён в исходники сервиса quota.
