# Интеграция приложения с API объединения

API одинаков для сайта, бота и другого серверного приложения. Интегратор отвечает за пользователей, проверку владения исходными подписками, покупки и продления. `remna-quota` хранит состав наборов, выдаёт общую ссылку и читает отдельные показатели источников.

## Модель

**Bundle** — самостоятельная объединённая подписка. ID выбирает приложение: например UUID отдельной подписки или записи конструктора. ID содержит 1–80 латинских букв, цифр, `_` или `-`; `resolve` зарезервирован. Несколько наборов могут иметь одинаковое название или `external_ref`.

**Source** — ссылка на существующую подписку: `provider` + `reference`. Для Remnawave `reference` — положительный числовой ID пользователя панели строкой. Его username, сквады и описание не изменяются. Ключ источника — 1–32 строчных латинских символа, цифры, `_` или `-`, первый символ — буква.

`external_ref` — необязательное непрозрачное значение длиной до 128 символов для фильтрации. Например, ID пользователя приложения. Это метаданные, а не проверка прав. `metadata` — до 16 строковых полей: ключи по правилам ключа источника, значения до 256 символов. Не сохраняйте в них секреты.

Сначала вызовите `GET /api/v1/capabilities`: ответ содержит настроенные провайдеры, `max_sources`, форматы и признак включённого API создания пользователей. В деморежиме существуют источники `demo/main` и `demo/cdn`.

## Создание набора и повторы

```http
PUT /api/v1/bundles/subscription-123
Authorization: Bearer <server-api-key>
Content-Type: application/json

{
  "name": "MAIN + CDN",
  "external_ref": "application-user-42",
  "metadata": {"channel": "telegram"},
  "enabled": true,
  "sources": [
    {"key":"main","label":"MAIN","provider":"remnawave","reference":"101","enabled":true},
    {"key":"cdn","label":"CDN","provider":"remnawave","reference":"102","enabled":true}
  ]
}
```

Замените ID на реальные. Никаких запросов записи в панель не выполняется. `200` означает, что состав сохранён; существование и состояние источников наблюдаются при `refresh`, фоновой проверке и загрузке общей ссылки. До первого чтения статистика источника равна `null`, `status: "pending"`. Пустой массив `sources: []` допустим для незаполненного конструктора и выдаёт пустой документ.

Повторяйте запрос с **тем же ID**, если результат потерян из-за тайм-аута: состав и токен сохраняются. Новый ID означает новый независимый набор. Поэтому новая покупка и повтор одного webhook должны получать разные и одинаковые ID соответственно — это выбирает вызывающее приложение.

`PUT` полностью заменяет состав. Непереданные источники отсоединяются; исходные подписки не удаляются. Нельзя дважды включить один `provider/reference` в один набор. В разных наборах это разрешено, но счётчик и VPN-учётные данные останутся общими для этой исходной подписки.

## Конструктор и атомарное изменение одного источника

Приложение получает выбранные обычную подписку и CDN, проверяет права пользователя на них и передаёт массив `sources`. Имена `main` и `cdn` — соглашение приложения: сервис не знает тарифов, количества устройств или стоимости.

Для добавления CDN к уже существующему набору:

```http
PUT /api/v1/bundles/subscription-123/sources/cdn
Authorization: Bearer <server-api-key>
Content-Type: application/json

{"label":"CDN","provider":"remnawave","reference":"102","enabled":true,"expected_revision":1}
```

MAIN не затрагивается. Повтор с актуальной версией и теми же настройками не увеличивает `revision`. Чтобы временно исключить CDN, передайте тот же источник с `enabled: false`. Чтобы отсоединить его, вызовите `DELETE .../sources/cdn?expected_revision=2`.

`PATCH /api/v1/bundles/{id}` меняет только `name`, `external_ref`, `metadata` или `enabled`; переданный объект `metadata` заменяет метаданные целиком. Например `{"enabled":false,"expected_revision":3}` сразу закрывает общую ссылку. VPN-пользователи при этом не отключаются.

## Конкурентные изменения

Ответ содержит `revision` состава. Для PUT/PATCH передавайте её в `expected_revision`, для DELETE и `POST .../rotate-token` — в одноимённом query-параметре.

- `expected_revision: 0` у полного PUT разрешает только создание отсутствующего набора.
- Несовпадение возвращает `409 {"error":"revision_conflict"}` без изменения данных.
- После конфликта перечитайте набор, пересчитайте изменение и повторите его с актуальной версией.
- Без проверки версии действует последнее принятое изменение. Операции над отдельным источником всё равно атомарны и не перезаписывают соседние источники.
- Обновление статистики не меняет `revision`. Изменение состава, метаданных, включения или токена меняет её.

Повтор после потерянного ответа с прежней `expected_revision` может получить `409`, если первый запрос уже применён. Проверьте состояние, прежде чем повторять бизнес-операцию. Повторная ротация без условия версии создаёт ещё один токен.

## Статистика и доступность

`GET /api/v1/bundles/{id}` читает сохранённые данные. `?refresh=true` или `POST .../refresh` обновляет их из панели. Фоновое чтение регулируется `BACKEND_SYNC_INTERVAL`.

| Поле источника | Значение |
| --- | --- |
| `used_bytes` | Расход, `null` до успешного чтения |
| `limit_bytes` | Лимит панели; `0` — безлимит, `null` — неизвестно |
| `unlimited` | `true`/`false` по наблюдаемому лимиту, `null` до чтения |
| `remaining_bytes` | Остаток с нижней границей 0; `null` для безлимита/неизвестного расхода |
| `expires_at` | Наблюдаемый срок исходной подписки |
| `status` | `active`, `disabled`, `expired`, `limited`, `pending`; `excluded` при исключении из набора |
| `stale`, `checked_at` | Актуальность и время последнего успешного чтения |
| `last_error` | Санитизированная ошибка источника, без URL/ключей |

Статус набора `ready` означает, что включённые источники наблюдались без ошибки, но **не** что каждый источник активен: проверяйте их статусы. `pending` — ещё нет снимка, `error` — ошибка наблюдения включённого источника, `disabled` — общая ссылка выключена. `stale` дополнительно учитывает возраст снимка: по умолчанию `max(2 * sync interval, 2 минуты)`.

Ошибка источника при refresh сохраняется в ответе `200` вместе с прежним снимком; данные не выдаются за актуальные. При загрузке общей ссылки любой сбой включённого источника возвращает `503`, без неполного списка. Известно заблокированный/истёкший/исчерпанный источник пропускается независимо. Если доступных подключений нет, возвращается `200` с пустым документом.

## Список, ссылка и удаление

`GET /api/v1/bundles?external_ref=application-user-42&limit=50` возвращает `items` и `next_cursor`. Передавайте курсор без изменения и с тем же фильтром. Размер страницы 1–100, по умолчанию 50; порядок — по ID. При конкурентном изменении состава списка это обход страниц, а не снимок единой транзакции.

`POST /api/v1/bundles/resolve` принимает `{"subscription_url":"https://<public-origin>/sub/<token>"}` и возвращает набор. Принимается только URL из `BACKEND_PUBLIC_URL`, без query/fragment/credentials; внешней загрузки URL нет. Метод пригоден для проверки ссылки любым интегратором. Он не создаёт сессию пользователя и не подтверждает оплату.

`POST .../rotate-token` отзывает старый URL. `DELETE /api/v1/bundles/{id}` возвращает `204` и удаляет только набор и токен. Повтор DELETE отсутствующего набора возвращает `404`; приложение может считать это уже достигнутым результатом. Удаление, исключение источника и смена токена не отзывают нативную ссылку панели и скачанные учётные данные.

## Go SDK

```go
api, err := client.New(os.Getenv("QUOTA_API_URL"), os.Getenv("QUOTA_API_KEY"))
if err != nil { return err }

result, err := api.PutBundle(ctx, subscriptionID, client.PutBundleRequest{
    Name: "MAIN + CDN", ExternalRef: ownerID, Enabled: true,
    Sources: []client.SourceReference{
        {Key: "main", Label: "MAIN", Provider: "remnawave", Reference: mainID, Enabled: true},
        {Key: "cdn", Label: "CDN", Provider: "remnawave", Reference: cdnID, Enabled: true},
    },
})
if err != nil { return err }
// result.SubscriptionURL — общая ссылка для получателя.
observed, err := api.GetBundle(ctx, result.ID, true)
```

Импорт: `github.com/saidovux/remna-quota/pkg/client`. До публикации этой рабочей копии используйте локальный `replace`; затем закрепите проверенный тег/коммит. Клиент переиспользуется между запросами. Методы: `Capabilities`, `PutBundle`, `GetBundle`, `PatchBundle`, `ListBundles`, `PutSource`, `RemoveSource`, `RefreshBundle`, `ResolveBundle`, `RotateBundleToken`, `DeleteBundle`. Ошибки HTTP представлены `*client.APIError` с `StatusCode`/`Code`.

Чтобы подключить Telegram-бота, настройте те же адрес/ключ, выберите схему ID и вызовите эти методы из обработчиков бота. Формат API и серверная конфигурация remna-quota от типа клиента не меняются. Пример HTTP-клиента на Python находится в [examples/python](../examples/python).

## Доверие и расширение

Серверный ключ административный: его держит доверенный бэкенд. Он не должен попадать во фронтенд или к пользователю Telegram. Изолируйте API в приватной сети либо публикуйте через HTTPS. Приложение проверяет, кому разрешено видеть набор и исходные подписки; `external_ref` не является механизмом авторизации.

Адаптеры реализуют `internal/aggregate.Provider` с двумя методами: `Read` и `Links`. Интерфейс не включает изменения пользователя. Сейчас доступны Remnawave v3 и demo; API не загружает произвольные сторонние URL. Основной API создания и синхронизации пользователей описан в [integration.md](integration.md).
