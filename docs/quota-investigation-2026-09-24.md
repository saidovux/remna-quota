# Проверка квот на стоковой Remnawave / Xray

Дата: 24 сентября 2026. Remnawave 3.4.3, ноды remnawave/node:3.1.1, Xray 26.7.28.

Это отчёт первоначального исследования. Последующие исправления и проверка установленной версии описаны в [отчёте выпуска надёжности](reliability-release-2026-09-24.md).

Обновление 24 сентября, 21:06 МСК: по поручению владельца коэффициент пользовательского расхода MAIN переведён с `0` на `1` штатным API панели. Описанная ниже причина нулевого расхода MAIN устранена настройкой; Xray не изменялся.

## Результат

remna-quota остаётся менеджером стандартного API Remnawave. Ноды, их конфигурация и ядро Xray не изменялись. Эксперимент с отдельным патчем Xray остановлен по указанию владельца, файлы патча удалены из проекта. Патч не развёртывался. Создание дополнительной ноды не выполнялось.

Исправлен и развёрнут расчёт нативного лимита в remna-quota: превышение квоты больше не повышает её до фактического расхода. При пакете 50 000 000 байт и расходе 76 944 860 байт лимит панели возвращён к 50 000 000, расход сохранён, пользователь остаётся отключённым. Резервная копия собственной БД сделана перед обновлением.

## Причины

1. **Нулевой расход MAIN.** Frankfurt имеет `consumptionMultiplier = 0`. Remnawave умножает пользовательский расход на ноль. На том же узле ещё 26 подписок с лимитами, поэтому изменение общего коэффициента затронуло бы их. Настройка сохранена по указанию не изменять ноды. Номинальный пакет MAIN 100 MB при этой конфигурации фактически не списывается.
2. **Повышение лимита после перерасхода.** Формула `текущий счётчик + max(0, остаток)` при отрицательном остатке делала нативный лимит равным перерасходу. Новая формула вычитает из логического пакета списания прошлых эпох счётчика и сохраняет исходный порог текущей эпохи. Ноль не передаётся как исчерпанная квота, поскольку в панели он означает безлимит.
3. **Задержка учёта.** В установленной панели пользовательские счётчики собираются раз в 15 секунд. Cron проверки исчерпания — `*/45`, то есть на 0-й и 45-й секундах минуты. Чаще опрашивать API remna-quota недостаточно: панель ещё не получила новые значения.
4. **Открытые соединения.** Штатный VLESS `RemoveUser` в Xray удаляет пользователя из валидатора, но не закрывает уже аутентифицированные потоки. `connections/drop` в установленной Remnawave Node получает IP пользователя и уничтожает сокеты по IP с использованием `NET_ADMIN`; это не точное закрытие его сессий за CDN/обратным прокси. Автоматический вызов такого маршрута в remna-quota не добавлен.

## Реальный тест CDN

Отдельный временный пользователь имел пакет 5 000 000 байт. Непрерывная загрузка через XHTTP/CDN шла с контролируемого тестового HTTP-сервера приблизительно по 512 KiB/s.

| Секунды от начала | Статус панели | Учтено панелью, байт | Получено клиентом, байт |
|---:|---|---:|---:|
| 10,0 | ACTIVE | 3 304 288 | 5 111 808 |
| 22,1 | ACTIVE | 11 168 608 | 11 403 264 |
| 26,1 | DISABLED | 11 168 608 | 13 500 416 |
| 44,1 | DISABLED | 19 032 928 | 22 937 600 |

Открытая загрузка продолжалась минимум 18 секунд после наблюдения `DISABLED`. Её остановил тестовый клиент, а не квота. Это подтверждает ограничение на реальном соединении, а не только по статусу API. Тестовые пользователи, контейнеры клиентов и HTTP-сервер удалены; подписка тестовый аккаунт сохранена.

## Проверки исправления remna-quota

- Повторная синхронизация после перерасхода не повышает лимит и не включает пользователя.
- Исправление ранее завышенного лимита, состояния ACTIVE/LIMITED/DISABLED, сбросы счётчика и пересоздание пользователя покрыты тестами.
- `go test ./...` и `go vet ./...` проходят. PostgreSQL-интеграция в этом запуске отдельно не выполнялась.
- На сервере подтверждены лимит CDN тестовый аккаунт 50 000 000 байт, расход 76 944 860 и отключённое состояние. Общая ссылка и идентификаторы сохранены.
- На обеих нодах сохранён исходный бинарник Xray с SHA-256 `64d46afb80adea1bf97a0d467e83f4a9ac1ebd0995891e84bca3f1a1d1affb1d`; контейнеры не пересоздавались и не перезапускались.

## Ограничение результата

Без изменения текущей инфраструктуры нельзя подтвердить строгое отключение CDN ровно при исчерпании пакета, включая уже открытые соединения. MAIN при нулевом коэффициенте тоже не обеспечивает расходуемые 100 MB. Исследование патчей остановлено по указанию владельца. Затем по новому поручению продолжены исправления только remna-quota; два ограничения инфраструктуры оставлены открытыми.
