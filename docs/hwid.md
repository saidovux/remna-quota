# Общий лимит устройств (HWID)

`device_limit` принадлежит аккаунту — приобретённой объединённой подписке. Значение `3` означает три устройства для всех её частей вместе. Один HWID получает MAIN и CDN и занимает один слот. Другая покупка имеет собственный аккаунт и отдельные слоты.

```http
PATCH /api/v1/accounts/test-account
Authorization: Bearer <BACKEND_API_KEY>
Content-Type: application/json

{"device_limit": 3}
```

Поле также принимается в `PUT /api/v1/accounts/{id}`. Диапазон: 0–1000; `0` отключает проверку. Пропущенное или `null` поле сохраняет прежнюю настройку; новый аккаунт без поля создаётся без ограничения. Снижение ниже числа зарегистрированных устройств возвращает `409 account_conflict`: сначала удалите лишние устройства. Настройка поддерживает `expected_revision`, синхронизацию в фоне и ответ `202`.

Ответ аккаунта содержит `device_limit` и `device_count`. Подробный список доступен только доверенному приложению:

* `GET /api/v1/accounts/{id}/devices` — `{device_limit, device_count, items}`.
* `DELETE /api/v1/accounts/{id}/devices/{hwid}` — освобождает слот во всех частях; повторное удаление безопасно. Возвращает аккаунт, `200` или `202`.

Go SDK: `PutAccountRequest.DeviceLimit`, `PatchAccountRequest.DeviceLimit`, `ListDevices`, `DeleteDevice`. API не зависит от сайта и подходит для бота или административного интерфейса. Приложение самостоятельно проверяет право пользователя управлять аккаунтом; ключ quota нельзя выдавать браузеру.

## Получение подписки

При положительном лимите клиент передаёт `x-hwid`, соответствующий `^[a-zA-Z0-9=-]{10,64}$`. Дополнительно принимаются `x-device-os`, `x-ver-os`, `x-device-model`, `user-agent`. Метаданные длиннее 256 байт или с управляющими символами игнорируются. IP не используется как идентификатор устройства.

* Нет корректного HWID: `403 hwid_required`, `x-hwid-not-supported: true`.
* Новое устройство сверх лимита: `403 device_limit_reached`, `x-hwid-max-devices-reached: true`, `x-hwid-limit: true`.
* Уже зарегистрированное устройство продолжает получать подписку при заполненном лимите.
* При включённой проверке возвращается `x-hwid-active: true`.
* Ошибка подтверждения состояния панели: `503`; частичные подключения не выдаются.

Используйте совместимый клиент, например Happ или v2RayTun. Открытие защищённой ссылки обычным браузером без HWID не возвращает подключения. Вход в кабинет по ссылке через защищённый API разрешения ссылки не занимает устройство.

HWID ограничивает получение и обновление подписки. Это не счётчик одновременных VPN-соединений: скопированные ключи, подменённый HWID и уже загруженные конфигурации нельзя надёжно заблокировать этим механизмом. Удаление устройства освобождает слот, но не отзывает ранее скачанные VPN-ключи. [Штатное поведение Remnawave](https://github.com/remnawave/panel/blob/main/docs/features/hwid-device-limit.md).

## Синхронизация с Remnawave

Quota хранит общий реестр в PostgreSQL, в состоянии аккаунта. Регистрация и операции панели сериализуются отдельной блокировкой аккаунта между репликами, без сетевых вызовов внутри SQL-транзакции. Слот сохраняется до записи в панель; повтор после тайм-аута или перезапуска использует тот же HWID. Ротация ссылки, продление, исчерпание CDN и пересоздание пользователя панели не обнуляют список устройств.

Через штатные `/api/users` и `/api/hwid/devices` quota устанавливает одинаковый `hwidDeviceLimit` и одинаковый список HWID всем частям, в том числе временно отключённым. Удалённые в панели устройства восстанавливаются из quota, а добавленные отдельно в панели удаляются при следующей синхронизации. Управлять устройствами объединённых подписок нужно через quota. Отдельные нативные ссылки пользователей панели покупателям не выдаются: общий лимит применяется на общей ссылке quota.

API-токену панели дополнительно нужны `hwid-user-devices:list-by-user`, `hwid-user-devices:create`, `hwid-user-devices:delete` (Remnawave v3). Административный JWT в runtime не используется.

Чтобы включить штатную проверку панели только для пользователей quota, создайте отдельный External Squad с `hwidSettings.enabled=true` и укажите его UUID в `REMNAWAVE_HWID_EXTERNAL_SQUAD_UUID`. Для аккаунтов с явно заданным `device_limit` quota назначает этот squad. Настройки остальных пользователей и глобальный HWID остаются прежними. Если переменная не задана, существующий External Squad сохраняется; глобальные/групповые настройки HWID администратор задаёт отдельно. Собственная проверка общей ссылки quota действует независимо от глобального переключателя панели.

Ноды и Xray остаются штатными. Remnawave продолжает измерять трафик и ограничивать каждую часть независимо.

## Обновление

Поля добавлены в существующее JSON-состояние аккаунта; SQL-миграция не нужна. Старые записи без поля сохраняют поведение. Перед выпуском сохраните БД, бинарный файл и окружение. Старую и новую версии обработчика одновременно не запускайте: старая версия не сохраняет новые поля при перезаписи JSON. Для отката после регистрации устройств нужно учитывать сохранённые в панели лимиты и настройки группы.
