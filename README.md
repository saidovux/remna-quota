# remna-quota

Самостоятельный Go-бэкенд для создания пользователей, управления независимыми квотами и объединения VPN-подписок в одну ссылку. У сервиса своя PostgreSQL и REST API: им могут пользоваться сайт, Telegram-бот или будущая панель управления.

Основной объект — **аккаунт с объединённой подпиской** (`account`). В нём от 1 до 8 частей (`parts`), например MAIN и CDN. Для каждой части remna-quota создаёт отдельного пользователя Remnawave: `alice_main`, `alice_cdn`. У них разные учётные данные, счётчики, лимиты и сроки, а клиент получает один `subscription_url`.

Цены, платежи и правила покупки задаёт вызывающее приложение. remna-quota принимает технические параметры доступа: лимит в байтах, срок, профиль и состояние.

Пример работающего подключения Go-сайта через этот API: [интеграция FutcinVPN](docs/futcinvpn-integration.md).

## Как работает трафик

- MAIN может быть безлимитным (`limit_bytes: 0`), а CDN — иметь пакет 70 GiB (`75161927680` байт). Обе части также могут иметь свои конечные лимиты.
- VPN-ноды измеряют трафик, Remnawave предоставляет счётчики. remna-quota сохраняет расход отдельно для каждой части, рассчитывает остаток и синхронизирует ограничения панели.
- При исчерпании CDN сервис отключает его пользователя в панели и исключает CDN из общей выдачи. MAIN продолжает работать в пределах своего срока и лимита.
- Для `NO_RESET` уже учтённый расход сохраняется даже после сброса счётчика или пересоздания пользователя в панели. Нативная квота пересчитывается под оставшийся пакет. Периодические стратегии используют циклы сброса Remnawave.
- Увеличение лимита и продление сохраняют пользователей, общую ссылку и учтённый расход. Повтор запроса с тем же ID не создаёт дубликаты.

Remnawave измеряет трафик и применяет ограничения; remna-quota управляет настройками через стандартный API. Патчи Xray и нод не требуются. Задержка сбора статистики допускает перерасход, а уже открытые соединения могут продолжаться после отключения пользователя — это ограничение установленной Xray. Учёт `NO_RESET` использует накопительный счётчик панели; неизвестный расход удалённой записи восстановить нельзя. Подробности — [учёт трафика и синхронизация](docs/traffic-accounting.md).

## API для сайта, бота и будущего интерфейса

| Метод | Назначение |
| --- | --- |
| `PUT /api/v1/accounts/{id}` | Создать или настроить аккаунт и его части |
| `GET /api/v1/accounts` | Список с курсором, поиском по началу username, фильтрами enabled и external_ref |
| `GET /api/v1/accounts/{id}?refresh=true` | Получить аккаунт и свежие показатели каждой части |
| `PATCH /api/v1/accounts/{id}` | Изменить название, внешнюю привязку или включение всего аккаунта |
| `PUT /api/v1/accounts/{id}/parts/{key}` | Добавить или изменить одну часть, сохранив настройки остальных |
| `POST /api/v1/accounts/{id}/sync` | Немедленно применить сохранённые настройки |
| `POST /api/v1/accounts/{id}/rotate-token` | Заменить общую ссылку |
| `GET /api/v1/capabilities` | Получить возможности и доступные профили |
| `POST /api/v1/subscriptions/resolve` | Проверить общую ссылку перед созданием сессии во внешнем приложении |
| `GET /sub/{token}` | Общий URI-список в Base64; `?format=plain` — обычный текст |

Административные методы защищены `Authorization: Bearer <BACKEND_API_KEY>`. Один клиент приложения может иметь несколько независимых аккаунтов с одинаковым `external_ref` и разными ID/username. Защита от конкурентной перезаписи — `expected_revision`. Цены и поля платежей API не принимает.

В ответе есть общая ссылка и состояние аккаунта, а внутри `parts` — отдельные расходы, остатки, сроки и состояние синхронизации. Суммарная квота для MAIN+CDN не выдумывается. Запись настроек ждёт синхронизации до пяти секунд, затем возвращает `202`; обработка продолжается в фоне, даже если клиент отключился. Одновременно обрабатываются до четырёх аккаунтов. Повторы с задержкой и `Retry-After` сохраняются в PostgreSQL.

`observed_at`, `applied_revision`, `accounting_status` и `next_retry_at` позволяют отличить свежую статистику от подтверждённых настроек. Защищённые Bearer-ключом `GET /api/v1/diagnostics` и `GET /api/v1/metrics` показывают очередь, ошибки и возраст наблюдений без обращения к панели и без пользовательских секретов.

## Быстрый запуск без панели

Нужен Go 1.27.x. Скопируйте `.env.example` в `.env`, сгенерируйте ключ командой `go run ./cmd/quota-api keygen` и сохраните его в `BACKEND_API_KEY`.

```bash
go run ./cmd/quota-api check-config
go run ./cmd/quota-api serve
```

По умолчанию `BACKEND_PROVIDER=demo`: данные хранятся в памяти, подключения демонстрационные. Пример создания MAIN+CDN приведён в [интеграции](docs/integration.md). Деморежим также запускается через `docker compose -f compose.demo.yaml up --build -d`.

## Рабочая установка

`compose.yaml` запускает API с отдельной PostgreSQL. Для Remnawave задайте адрес, серверный API-токен и сопоставление профилей MAIN/CDN внутренним сквадам. Управление пользователями включено по умолчанию: `BACKEND_ENABLE_MANAGED_ACCOUNTS=true`. Фоновый цикл синхронизации — 10 секунд по умолчанию; время обработки всех аккаунтов и задержки панели могут увеличить фактический интервал.

[Развёртывание и резервные копии](docs/deployment.md) · [Безопасность](docs/security.md) · [Выполненные проверки и ограничения](docs/verification.md)

[Исправления и результат серверной проверки 24 сентября 2026](docs/reliability-release-2026-09-24.md).

Сервис создаёт и изменяет только своих пользователей по маркеру принадлежности. Настройки доступа задаются через remna-quota; ручные изменения лимитов, сроков и сквадов в панели будут приведены к сохранённой конфигурации. Произвольные существующие записи автоматически не присваиваются.

## Дополнительное объединение существующих подписок

Сохранён API `/api/v1/bundles`: он объединяет явно указанные существующие подписки без управления их пользователями. Это отдельный сценарий с учётом и блокировкой на стороне исходного провайдера. [Описание](docs/integration-aggregation.md), [контракт](docs/openapi-aggregation.yaml). Только для такого использования можно явно выключить managed API через `BACKEND_ENABLE_MANAGED_ACCOUNTS=false`.

## Границы и разработка

Реализованы Remnawave v3 и demo; другой провайдер подключается адаптером `bundle.Provider`. Одна установка сейчас использует один адрес панели. Формат выдачи — URI-список plain/Base64; Clash YAML и sing-box JSON не реализованы. Общий административный ключ предназначен доверенным приложениям; авторизация конечных пользователей остаётся у интегратора.

При ошибке доступного провайдера общая выдача возвращает `503`, чтобы не подменять рабочий список случайно неполным. Известные отключённые, истёкшие и исчерпанные части исключаются независимо.

```bash
go test ./...
go vet ./...
go build ./...
```

[Разработка и интеграционные тесты](docs/development.md). Прежний контроллер с Bedolaga сохранён в [архиве](docs/legacy-controller.md) и не участвует в работе `quota-api`.

Общий лимит устройств для MAIN и CDN задаётся через `device_limit` аккаунта. Список и удаление устройств доступны через API. См. [HWID](docs/hwid.md).
